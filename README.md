# Wikipedia: зміна мови інтерфейсу авторизованим користувачем

E2E-автотест на **Playwright + TypeScript**, який перевіряє, що авторизований користувач Wikipedia може змінити мову інтерфейсу в розділі **Preferences → User profile → Internationalisation**. Тест запускається в Docker-контейнері, а HTML-звіт копіюється в локальну папку хост-машини.

## Тест-кейс

**Користувацький сценарій:** успішне перемикання мови інтерфейсу веб-додатка Wikipedia авторизованим користувачем.

- **Коли:** авторизований користувач переходить у розділ «Preferences», на вкладці «User profile» у розділі «Internationalisation» вибирає іншу мову інтерфейсу.
- **Тоді:** інтерфейс додатка відображається обраною мовою.

| Поле | Значення |
|---|---|
| **ID** | TC-01 |
| **Назва** | Успішна зміна мови інтерфейсу авторизованим користувачем |
| **Модуль** | Preferences → User profile → Internationalisation |
| **Пріоритет** | High |
| **Тип** | Функціональний, позитивний, E2E |
| **Середовище** | https://en.wikipedia.org, десктоп, Chromium, скін Vector 2022 |
| **Тестові дані** | Мова `uk · українська` (автотест додатково проганяє той самий кейс для `fr · français`) |

**Передумови**

1. Існує зареєстрований акаунт Wikipedia.
2. Користувач авторизований на https://en.wikipedia.org.
3. Поточна мова інтерфейсу користувача: `en · English`.

**Кроки**

| # | Дія | Очікуваний результат |
|---|---|---|
| 1 | Відкрити головну сторінку (Main Page), відкрити меню користувача (Personal tools) і натиснути **Preferences**. | Відкрилась сторінка `Special:Preferences` із заголовком «Preferences». |
| 2 | Перейти на вкладку **User profile**. | Вкладка «User profile» активна. Відображається розділ **Internationalisation**, у полі **Language** вибрано «English». |
| 3 | Клікнути на поле **Language**, ввести `uk` і вибрати у списку `uk · українська`. | У полі відображається «українська», кнопка **Save** активна. |
| 4 | Натиснути **Save**. | Сторінка перезавантажилась і відображається українською: повідомлення «Ваші налаштування збережено.», заголовок «Налаштування», активна вкладка «Особові дані», розділ «Інтернаціоналізація», кнопка «Зберегти»; `<html lang="uk">`. |
| 5 | Відкрити головну сторінку (Main Page). | Інтерфейс українською: вкладки «Читати» та «Переглянути історію», у полі пошуку підказка «Пошук у Wikipedia», `<html lang="uk">`. Вміст статті лишається англійською (`lang="en"`), тобто змінилась саме мова інтерфейсу. |

**Постумова:** повернути мову інтерфейсу `en · English` (автотест робить це автоматично через MediaWiki API).

## Швидкий старт

Потрібно:

- **Node.js 20+** і npm (для локального запуску та одноразової авторизації);
- **Docker** з Docker Compose v2;
- **акаунт Wikipedia** (реєстрація: https://en.wikipedia.org/wiki/Special:CreateAccount).

```bash
git clone <URL цього репозиторію>
cd <папка репозиторію>

npm ci
npx playwright install chromium

cp .env.example .env    # вписати WIKI_USERNAME і WIKI_PASSWORD
npm run auth            # одноразовий вхід, див. «Авторизація та CAPTCHA»
npm run docker:test     # запуск тесту в Docker
npm run report          # відкрити HTML-звіт
```

### Змінні середовища (`.env`)

| Змінна | Опис |
|---|---|
| `WIKI_USERNAME` | Ім'я користувача Wikipedia |
| `WIKI_PASSWORD` | Пароль |

Файл `.env` є в `.gitignore` і `.dockerignore`: його немає ні в репозиторії, ні в Docker-образі. У контейнер змінні передаються під час запуску (`env_file` у `docker-compose.yml`), а в коді читаються через `process.env` ([src/utils/env.ts](src/utils/env.ts)).

> Тест змінює налаштування акаунта (і відновлює їх), тому краще використовувати окремий тестовий акаунт.

## Авторизація та CAPTCHA

Користувача логінить окремий setup-проєкт Playwright ([tests/auth.setup.ts](tests/auth.setup.ts)). Він вводить логін і пароль із `.env` через UI і зберігає сесію (cookies, з опцією «Keep me logged in» до 1 року) у `playwright/.auth/user.json`. Тести стартують уже авторизованими. Якщо збережена сесія ще дійсна, повторний логін пропускається.

Wikipedia захищає вхід **hCaptcha** і вмикає її залежно від оцінки ризику (IP, акаунт, кількість спроб). Якщо капча з'явилась, її має пройти людина: автотест **не обходить** CAPTCHA. Тому:

```bash
npm run auth
```

Відкриється вікно Chromium, логін і пароль підставляться автоматично. Якщо Wikipedia попросить CAPTCHA, пройдіть її у вікні (на це є 5 хвилин). Сесія збережеться, і всі наступні запуски (локально і в Docker) її використають. Якщо капча не потрібна, логін проходить повністю автоматично, і `npm run auth` можна пропустити.

Якщо сесії немає, а Wikipedia вимагає CAPTCHA в headless-режимі (зокрема в Docker), setup-тест падає з підказкою виконати `npm run auth`.

## Запуск тестів

### У Docker

```bash
npm run docker:test
```

Це те саме, що `docker compose run --rm --build e2e`. Команда збирає образ на базі `mcr.microsoft.com/playwright:v1.64.1-noble`, запускає тести і видаляє контейнер.

Без npm (тільки Docker):

```bash
docker build -t wikipedia-interface-language-e2e .
docker run --rm --ipc=host --env-file .env \
  -v "$(pwd)/playwright-report:/app/playwright-report" \
  -v "$(pwd)/playwright/.auth:/app/playwright/.auth" \
  wikipedia-interface-language-e2e
```

Додаткові аргументи Playwright можна передати так: `docker compose run --rm e2e npx playwright test --grep uk`.

### Локально

```bash
npm test                         # усі тести (headless)
npm run test:headed              # з відкритим браузером
npm run test:ui                  # Playwright UI mode
npx playwright test --grep "uk"  # лише кейс для української
npm run typecheck                # перевірка типів TypeScript
```

## Де шукати звіт

Після запуску (і в Docker, і локально) HTML-звіт лежить у папці **`./playwright-report/`** у корені проєкту на хост-машині:

```bash
npm run report    # = npx playwright show-report, відкриває звіт у браузері
```

Або відкрийте `playwright-report/index.html` напряму.

Як звіт потрапляє на хост: у [docker-compose.yml](docker-compose.yml) папка `/app/playwright-report` контейнера змонтована в `./playwright-report` хоста (bind mount). Звіт записується одразу на хост і лишається там після видалення контейнера (`--rm`).

У звіті є кроки тест-кейсу (`test.step`) і скріншоти сторінок після зміни мови для кожної мови. Для впалих тестів додатково зберігаються скріншот, відео і trace.

## Технічні рішення

- **Page Object Model і фікстури.** Локатори й дії винесені в page objects, а тест читається як тест-кейс: кроки `test.step` відповідають крокам із таблиці вище.
- **Локатори не залежать від мови.** Мова інтерфейсу змінюється, тому структурні елементи шукаються за стабільними id і класами MediaWiki (`#pt-preferences`, `#ca-view`, `#prefcontrol`), а тексти перевіряються явно з тестових даних.
- **Очікувані тексти взяті з MediaWiki.** Переклади в [src/data/languages.ts](src/data/languages.ts) відповідають системним повідомленням MediaWiki (ключ указано в коментарях) і перевірені через API `allmessages`.
- **Data-driven.** Кейс проганяється для кількох мов (`TARGET_LANGUAGES`). Нова мова додається одним об'єктом даних.
- **Передумова й відкат через API.** Перед кожним тестом мова примусово скидається на English, після тесту відновлюється. Так перерваний попередній запуск не залишить акаунт в іншій мові. Сама перевірка сценарію виконується через UI.
- **Послідовний запуск** (`workers: 1`): усі тести змінюють налаштування одного акаунта.
- **Секрети не потрапляють у звіти.** Playwright показує введені значення в назвах кроків (`Fill "…"`) і в trace. Тому пароль вводиться через `evaluate` (крок називається просто «Evaluate»), а trace для setup-проєкту вимкнено.
- **Версії зафіксовано.** Версія `@playwright/test` у `package.json` збігається з тегом Docker-образу, тож браузери в контейнері відповідають версії раннера.
